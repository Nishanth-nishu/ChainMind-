1. PROJECT OVERVIEW
────────────────────────────────────────────────────────────────────────────────

ChainMind is an agentic AI framework for autonomous drug discovery research,
benchmarked against top-tier AI for Science conference standards (NeurIPS,
ICML). The core claim: multi-agent ReAct-style reasoning outperforms single-shot
LLM responses on pharmaceutical chemistry tasks.

Goal: Publish a rigorous benchmarking study comparing 8 agentic strategies
      across 4 task categories (molecular property, literature, KG, multi-step).

Platform: SLURM cluster, gnode118, 1x NVIDIA RTX 3090 (24GB VRAM)
Model:    Qwen/Qwen2.5-7B-Instruct served via vLLM on port 8100
Workspace: /scratch/nishanth.r/sys_elvle_ai/

3. BENCHMARK TASK CATEGORIES
────────────────────────────────────────────────────────────────────────────────

Category A — Molecular Property (40 tasks)
  Input: SMILES string + question about drug-likeness / logP / MW / etc.
  Scoring: ±5% numerical tolerance against RDKit reference values
  Tools needed: assess_lipinski_rules, get_canonical_smiles

Category B — Literature Retrieval (30 tasks)
  Input: "Find papers about X"
  Scoring: keyword recall ≥ 0.6 from expected keyword list
  Tools needed: web_search (DuckDuckGo via research_server.py)

Category C — Knowledge Graph Generation (15 tasks)
  Input: "Create a knowledge graph of metabolic pathways for compound X"
  Scoring: (1) Response contains ```mermaid code block,
           (2) ≥ N edges extracted, (3) required_concepts present
  Tools needed: NONE — this is a pure generation task
  ⚠️  CRITICAL: The model must output a properly formatted Mermaid diagram.
               ComputationalChemistAgent's system prompt DOES NOT instruct the
               model to produce Mermaid syntax for KG tasks → 0% Cat-C in run_v2.

Category D — Multi-Step Reasoning (15 tasks)
  Input: Multi-step compound analysis (combine A + B reasoning)
  Scoring: Composite score; ALL steps must pass their sub-threshold
  Tools needed: assess_lipinski_rules + web_search

5. AUDIT: WHY RUN 2 WAS WORSE (Root Cause Analysis)
────────────────────────────────────────────────────────────────────────────────

PROBLEM: TSR dropped from ~77% (Run 1 best) to ~60% (Run 2 best). All Cat-C = 0.

ROOT CAUSE 1 — `get_canonical_smiles` tool parameter name mismatch  [FIXED]
  The model sends: {"name": "Aspirin"}
  The tool read:   args.get("query", "")  → empty string → PubChem crash
  Error seen in logs: "identifier/cid cannot be None"
  Fix applied: molecular_server.py now accepts "query" OR "name" OR "compound"
  File: chainmind/mcp/molecular_server.py

ROOT CAUSE 2 — Category C scored 0.0% in ALL experiments  [NEEDS FIX]
  Cat-C tasks require the model to produce a ```mermaid knowledge graph block.
  The ComputationalChemistAgent system prompt only knows about molecular tools.
  It has no instruction to produce Mermaid syntax for KG tasks.
  In Run 1, the orchestrator may have routed Cat-C tasks to a KnowledgeGraphAgent
  or the system prompt had explicit Mermaid formatting instructions.
  Fix needed: Add Mermaid KG instructions to the agent system prompt, OR
              create a dedicated KnowledgeGraphAgent that wraps the LLM with
              a prompt that enforces ```mermaid output for graph tasks.

ROOT CAUSE 3 — SLURM's $ENVIRONMENT variable crashes Settings()  [FIXED]
  SLURM sets the variable ENVIRONMENT=BATCH automatically.
  Pydantic-settings reads this and fails validation:
    "Input should be 'development', 'staging' or 'production'"
  Fix applied: All SLURM scripts now export ENVIRONMENT="development" explicitly.
  File: run_full_selfcontained.sh, run_v2/run_full_v2.sh

ROOT CAUSE 4 — run_v2 workspace was missing the data/ folder  [PARTIALLY FIXED]
  run_v2 was created with `cp -r chainmind/ experiments/ scripts/` but NOT data/.
  The data/ folder contains the ChromaDB vector store used by RAG experiments
  (exp005_tool_rag, exp007_chem_rag).
  Fix needed: Copy or symlink data/ into any new run workspace.

ROOT CAUSE 5 — exp008_debate had TaskResponse.error missing  [FIXED]
  The original types.py reconstruction omitted the `error` field on TaskResponse.
  Fix applied: Added `error: Optional[str] = None` to TaskResponse in types.py.

ROOT CAUSE 6 — AgentContext missing conversation_history  [FIXED]
  base_agent.py reads context.conversation_history but it wasn't in the Pydantic model.
  Fix applied: Added `conversation_history: List[LLMMessage] = Field(default_factory=list)`

ROOT CAUSE 7 — MCPToolResult had `output` field, code expected `result` + `success`  [FIXED]
  The reconstructed types.py used `output: str` but base_agent.py reads
  `tool_result.result` and `tool_result.success`.
  Fix applied: Changed to `result: Any`, `success: bool = True`.

ROOT CAUSE 8 — LocalProvider missing served_model_name kwarg  [FIXED]
  router.py calls LocalProvider(model_id=..., base_url=..., served_model_name=...)
  but the reconstructed __init__ only took base_url.
  Fix applied: Added all three kwargs to LocalProvider.__init__.

ROOT CAUSE 9 — router.py latency_ms format crash kills ALL successful responses  [FIXED]
  router.py line 176: f"({response.latency_ms:.0f}ms)" crashes when latency_ms is None.
  This is caught by `except Exception` and re-raised as LLMAllProvidersFailedError,
  meaning every successful vLLM API call (200 OK) was silently discarded as a failure.
  Fix applied: (response.latency_ms or 0):.0f
  File: chainmind/llm/router.py
  Git: commit 9241ae0

ROOT CAUSE 10 — A2A registry crashes on AgentCard.role being a str not Enum  [FIXED]
  protocol.py line 58: card.role.value.lower() fails because role is str, not Enum.
  Fix applied: role_key = (role_raw.value if hasattr(role_raw, 'value') else str(role_raw)).lower()
  File: chainmind/a2a/protocol.py
  Git: commit 9241ae0

[DS-01] Mol-Instructions  ★★★★★  PRIMARY DATASET
  Source: Fang et al., NeurIPS 2023. HuggingFace: osunlp/Mol-Instructions
  Size: ~2.3M instruction-response pairs
  Tasks covered:
    - Molecule description generation (SMILES → text)        [Cat-A, Cat-D]
    - Property prediction (logP, MW, toxicity, ADME)         [Cat-A]
    - Forward/retro-synthesis reaction prediction             [Cat-D]
    - Molecule editing (add/remove functional groups)         [Cat-D]
    - Drug-likeness assessment (Lipinski, QED, SA score)     [Cat-A]
  Format: {"instruction": "...", "input": "SMILES", "output": "..."}
  How to use: Filter for property prediction + drug-likeness tasks (~500K)
  Command:
    pip install datasets
    from datasets import load_dataset
    ds = load_dataset("osunlp/Mol-Instructions", "Molecule-oriented Instructions")

[DS-02] SMolInstruct  ★★★★★  COMPLEMENTARY TO DS-01
  Source: Wang et al., 2024. HuggingFace: osunlp/SMolInstruct
  Size: ~3.4M small molecule instruction pairs
  Tasks: Property prediction, IUPAC naming, SMILES captioning
  Advantage: More diverse SMILES formats, better for robustness
  Format: {"input": "<SMILES>CC(=O)O</SMILES> Predict logP", "output": "1.31"}

[DS-03] ToolBench  ★★★★☆  FOR REACT/TOOL-CALLING BEHAVIOR
  Source: Qin et al., ICLR 2024. HuggingFace: ToolBench/ToolBench
  Size: ~126K tool-use instruction samples, 16K real APIs
  Tasks: Multi-step tool calling with ReAct-style reasoning traces
  Why critical: Our benchmark is 100% tool-calling (ReAct). The base model
                Qwen2.5 knows chemistry, but struggles to reliably format
                THOUGHT/ACTION/ACTION_INPUT/FINAL_ANSWER correctly.
  Filter: Keep chemistry-adjacent APIs (PubChem, Wikipedia chemistry)
  Format: Full multi-turn JSON with tool call + observation sequences

[DS-04] AgentInstruct (Microsoft, 2024)  ★★★★☆  SYNTHETIC AGENT DATA
  Source: Yin et al., 2024. arxiv: 2407.03502
  HuggingFace: microsoft/zetron-agentinstruct-1M-v1
  Size: 1M synthetic agent instruction examples
  Tasks: Tool use, web search, code, reading comprehension
  Why relevant: Improves general agentic reasoning (all 4 benchmark categories)
  Note: Synthetic but high quality via teacher model distillation

[DS-05] ChemBench  ★★★★☆  EVALUATION + FEW-SHOT
  Source: Mirza et al., 2024. HuggingFace: jablonkagroup/ChemBench
  Size: 7000+ expert-level chemistry Q&A
  Tasks: IUPAC naming, reactions, safety, lab protocols
  Use as: Evaluation holdout + few-shot examples in SFT data

[DS-06] InstructMol / SciInstruct  ★★★☆☆  SCIENTIFIC INSTRUCTION
  Source: Wei et al., 2024. HuggingFace: CAMEL-AI/SciInstruct
  Size: 500K scientific instruction pairs
  Tasks: General chemistry, physics, biology (mixed)
  Use as: Domain general pre-SFT warm-up data

[DS-10] ChainMind Successful Trace Dataset (BUILD THIS OURSELVES)
  Source: Run 1 results + Run 3 results (currently running)
  Method:
    1. From benchmark runs, extract all tasks where TSR=1.0 (passed)

    3. Format as instruction: {"instruction": task.query,
                               "output": full_successful_trace_as_string}
    4. This is GOLD DATA specific to our exact benchmark
  Size estimate: 100 tasks × 8 experiments × 3 runs = ~2400 examples (small but pure)
  Why powerful: Model learns the exact ReAct format + tool call patterns we need
  Script to build: scripts/build_sft_dataset.py (to be created)

[DS-11] ChainMind DPO Pair Dataset (PREFERENCE PAIRS)
  Source: Same benchmark runs
  Method:
    - chosen: successful trace (TSR=1.0, no hallucination)
    - rejected: failed trace for the SAME query (TSR=0.0, hallucination error type)

APPROACH 1: QLoRA SFT with Unsloth  [RECOMMENDED STARTING POINT]
  Method: Supervised fine-tuning with 4-bit quantized LoRA (QLoRA)
  Paper: Dettmers et al., QLoRA NeurIPS 2023
  Library: unsloth (2x faster than HuggingFace PEFT, 60% less VRAM)
  Config:
    r=64, lora_alpha=128 (higher ratio = stronger adaptation)
    target_modules=["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"]
    lora_dropout=0.05
    quant: 4-bit NF4 (nf4) with double quantization
    gradient_checkpointing=True
  VRAM estimate: ~12-14GB for Qwen2.5-7B (fits with 10GB headroom)
  Batch: per_device_train_batch_size=2, gradient_accumulation_steps=8
  LR: 2e-4 with cosine schedule, warmup 100 steps
  Epochs: 2-3 (with <50K examples)
  Training time on RTX 3090: ~2-4 hours for 10K examples
  Expected TSR gain: +8-15pp over base prompting
  Publication angle: "SFT on domain-specific traces improves agentic chemistry performance"

  Install:
    pip install "unsloth[colab-new] @ git+https://github.com/unslothai/unsloth.git"
    pip install --no-deps xformers trl peft accelerate bitsandbytes

  Key code pattern:
    from unsloth import FastLanguageModel
    model, tokenizer = FastLanguageModel.from_pretrained(
        model_name="Qwen/Qwen2.5-7B-Instruct",
        max_seq_length=4096,
        dtype=None,  # auto-detect
        load_in_4bit=True,
    )
    model = FastLanguageModel.get_peft_model(
        model, r=64, target_modules=[...], lora_alpha=128, ...
    )

APPROACH 2: DPO (Direct Preference Optimization)  [AFTER SFT]
  Method: Contrastive learning on (prompt, chosen, rejected) preference pairs
  Paper: Rafailov et al., DPO NeurIPS 2023
  Library: TRL (HuggingFace), DPOTrainer
  Prerequisites: Need a fine-tuned SFT model first (Approach 1)
  Data: DS-11 ChainMind DPO Pair Dataset
  VRAM: ~16-18GB with QLoRA base
  Config: beta=0.1, learning_rate=1e-5, batch_size=1, grad_accum=16
  Training time: ~1-2 hours for 500 pairs
  Expected gain: +5-10pp over SFT alone
  Publication angle: "Preference learning on benchmark traces aligns model with
                      deterministic reward signals, reducing hallucination"

  Key advantage: No need for human labelers — our ground_truth_validator IS
  the preference oracle. This is publishable as "automated preference learning
  for scientific agents."

APPROACH 3: GRPO (Group Relative Policy Optimization)  [MOST NOVEL/PUBLISHABLE]
  Method: Reinforcement learning from deterministic reward (like DeepSeek-R1)
  Paper: Shao et al., DeepSeekMath 2024; Guo et al., DeepSeek-R1 2025
  Library: TRL >= 0.12.0 (GRPOTrainer), or verl
  Reward function: Our ground_truth_validator.score_response() — ALREADY EXISTS!
    score = score_response(task, model_output)["score"]  # 0.0 - 1.0
  Method:
    For each query, sample G=8 completions from the policy model
    Compute reward for each using ground_truth_validator
    Normalize rewards within the group (no value network needed)
    Update policy to increase probability of high-reward completions
  VRAM: ~20-22GB (tight — need all optimizations: gradient checkpointing,
                    gradient_accumulation=16, flash_attn2)
  Training time: 8-12 hours for full ChainMind-bench (100 tasks × G=8 = 800 rollouts)
  Expected gain: +10-20pp over base (this is where RL really shines)
  Publication angle: "Using deterministic chemistry validators as reward models
                      for GRPO-based agentic fine-tuning eliminates the need
                      for human preference annotation" — this is a strong NeurIPS paper!

  VRAM reduction tricks for RTX 3090:
    - Flash Attention 2 (saves ~4GB)
    - torch.compile() 
    - reduce G from 8 to 4
    - Use vLLM offline for rollout generation (separate process)

APPROACH 4: Full Fine-tuning (NOT RECOMMENDED on RTX 3090)
  Qwen2.5-7B full fine-tuning requires ~56-80GB VRAM in bf16.
  RTX 3090 has 24GB — not feasible even with CPU offload for 7B.
  Skip unless you get access to A100/H100 (request via plafnet2 admin).

APPROACH 5: Prompt Tuning / Prefix Tuning (MINIMAL BASELINE)
  Only train soft prompt tokens, model frozen.
  VRAM: <8GB. Quality significantly lower than LoRA.
  Use only to establish a "parameter-efficient baseline" for the ablation table.
  Library: PEFT (HuggingFace)

APPROACH 6: Continued Domain Pre-training (OPTIONAL, PRE-SFT)
  Pre-train on raw chemistry text (ChEMBL docs, PubChem abstracts, arXiv chemistry)
  before instruction-tuning.
  Recommended: ONLY if base model shows poor SMILES understanding (unlikely for Qwen2.5)
  Time: Multi-day. Skip for now.
